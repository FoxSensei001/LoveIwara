# 标签词库可疑度审计（零成本信号）

给 `iwara_tags` / `oreno3d_tags` 两份词库做**纯离线**体检，产出一份「该先看哪几条」的工作单。

**不联网、不调 AI、不修改任何现有数据**，只用脚本能确定的信号。它的用途是**先量再造刀**：
在决定要不要做批量编辑器之前，先知道错的到底有多少、是哪几类。

```bash
dart run tool/tag_audit/audit.dart            # 产物写到 out/
dart run tool/tag_audit/audit.dart --top 50   # 顺便在终端打印前 50 条
```

产物：
- `out/report.md` —— 人看的报告（总览 + 前 200 条工作单）
- `out/worklist.json` —— 机器读的完整工作单，后续给编辑器和 AI 批次任务当输入

## 信号表

排序原则：**脚本能确定的信号一律排在需要 AI 判断的信号之前。** 同档内按 `workCount` 降序。

| 信号 | 权重 | 含义 | 谁能修 |
|---|---|---|---|
| `name_collision` | 1000 | 多个词条共享同一个日文原名，**且译名至今仍然完全相同**（尚未拆解） | 人工拆，修一组少一组 |
| `parser_split_risk` | 700 | 原名含空白，列表页解析器按 `\s+` 切碎 | 修解析器 |
| `stuffed_translation` | 500 | 原名不含并列符，译名却塞了多个候选（`/`、`、`、`・`） | 人工定夺 |
| `kana_left_in_zh` | 300 | 中文译名里残留假名 | 补译 |
| `script_mismatch` | 250 | zh-TW 里混进简体字 / zh-CN 里混进繁体字 | 改字 |
| `missing_translation` | 180 | 缺该语言译名 | 补译 |
| `suspicious_length` | 40 | 中文译名远长于原名，可能塞了解释 | 人工定夺 |
| `cross_lang_identical` | 30 | 四语言全同（原名非拉丁时才算） | 弱信号 |
| `latin_untranslated` | 20 | 拉丁原名原样保留 | **不是错**，是「要不要给中文名」的编辑决策 |

## 为什么这些信号长这样（假阳性是怎么被削掉的）

第一版跑出 1062 条，其中大半是误报。逐条收紧后是 262 条：

- **`same_as_source` 曾误报 533 次**：繁体译名与日文汉字原名相同（`白露`→`白露`）是**正确答案**，不是没翻。
  现在只在原名不含汉字（纯拉丁/纯假名）时才算，并改名为 `latin_untranslated` 降级为决策项。
- **`stuffed_translation` 曾把忠实翻译判成错**：`タイツ・ストッキング`→`裤袜/丝袜`、
  `FGO（Fate/Grand Order）` 的斜杠都是**原名自带的并列**。现在只在**原名不含并列符**时才算。
- **`kana_left_in_zh` 曾把 `・` 当成假名**：U+30FB 落在片假名区，但它在中文译名里是合法分隔符。已排除。
- **`cross_lang_identical` 曾误报 271 次**：`Apple Pie`、`RWBY` 这类拉丁原名四语言相同是正确答案。
  现在只在原名含汉字或假名时才算。
- **`suspicious_length` 曾按英文长度误判**：`淫乱`→`Slutty / Lewd` 是正常义项并列。现在只看中文侧。

简繁检测用 `cjk_variants.dart` 的两张「独用字」表（各 285 字），只收对方字集里几乎不出现的高频字，
两岸共用字（美、里、骨、鹿、黑、云、干、面、后…）一律不收——否则会把正常译名全判成简繁混用。
两张表的交集必须为空。

## 已知未覆盖

- **身份冲突**（译名指向的作品 ≠ 词库里的 origin）需要查 Danbooru / Wikidata，属于联网的确定性层，不在本脚本内。
- **三方分歧**（多家 agent 给出不同译名）需要 AI 批次跑完才有。
- 本脚本**不判断译名对不对**，只判断它「看起来有没有问题」。`ホタル`→`流萤` 在本脚本眼里
  唯一的问题是 `name_collision`，至于哪个 ホタル 该叫流萤，得人来定。
